Frankenstein Variorum

Jun 2022 – Dec 2023

Research Assistant & Co-author · Digital Humanities Lab, Penn State

  • Pipeline automation
  • Viewer UX
  • Root-cause fixes
Starting point
A multi-year digital research project comparing five editions of Frankenstein (1816–1831). I started by running its data scripts, proofreading the output and logging errors.
How it grew
Pair programming with my advisor, Elisa Beshero-Bondar, I worked out what the scripts did and proposed fixes for the errors behind them. Once debugging had shown me what every code file did, I took on automating the collation step and then the post-collation pipeline, more than a dozen scripts that now run as one command in about 2.5 hours, so new proofreaders could process data themselves while I fixed what their feedback found.
Then the website
I proposed testing the processed data on the website, learned React from zero on a starter Astro project, and rebuilt the prototype into the project's public viewer: smooth switching between editions, jumping straight to a variant in context, and chapters that line up even when editions number them differently.
Outcome
Code in five of the project's repositories, a co-author credit on the project, a talk at the 2023 Keystone Digital Humanities Conference, and a tool now used at other universities.

ScheduleEase

2023

The question"What do I still need to graduate?" Penn State's CS and SE degree requirements are nested and full of exceptions, and students lose track of them.

Actually neededA trustworthy answer, checked against every rule, built from data students actually have.

What I didRules too tangled to check by hand. The requirements nest and carry exceptions, so I modeled them as structured data that a rule-matching engine can check a student's record against.

No source for completed courses. There was no API to pull them, so I used the unofficial transcript students can export from the school portal, and wrote a parser that gets clean course records out of its malformed HTML.

ResultCaught real discrepancies before they could mislead a student, such as honors sections not being counted toward the base course they satisfy.

  • Java
  • Spring Boot
  • Rule engine
  • HTML parsing

Measuring Student Engagement

2023 – 2024

The questionResearchers wanted to measure how engaged students are while they read and watch course material. Teammates built the eye tracking and facial-expression analysis.

Actually neededOne ready-to-run tool that takes a participant through a whole session, from consent and a pre-survey through the reading, video and quiz, while those modules record alongside, without crashing partway.

What I didEvery participant must go through the same steps. I built the controller that runs the session in order, from consent to the final quiz, while my teammates' modules record alongside.

Study materials must be easy to read. The consent form, instructions, surveys, and each reading or video with its quiz live in YAML files, one folder per material. YAML's indented syntax reads like the Python codebase, so people and scripts can both read it.

Sessions must run reliably. Every so often, without a clear pattern, a session crashed. The lab computer has one webcam, but each part of the app opened its own connection to it, and now and then those connections collided. I made the app open the camera once and share that one connection with every part that needs it, which ended the random crashes.

ResultRan real sessions with 17 participants and produced a dataset the team validated their models against.

  • Python
  • PyQt5
  • OpenCV

Applied AI · Four-day build · 3-person team

AI Chatbot with Knowledge Base

2025

The questionHow can an existing desktop app get a chatbot that answers from its own data, without a complex integration?

What I didPlug into any app, with any data. Even in a four-day build, I designed the architecture first: the knowledge base, the language-model client and the chat history sit behind interfaces, so each can be swapped without touching the others, and two teammates could build the rest in parallel. The knowledge base reads any object's fields with Java Reflection, so pointing the chatbot at new data means handing it different objects, not writing new code. The prompt keeps answers to that data, and the chatbot declines when the data can't answer.

  • Gemini API
  • JavaFX
